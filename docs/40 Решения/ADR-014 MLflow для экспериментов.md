# ADR-014 MLflow для экспериментов с оценкой

**Статус:** принято · **Дата:** 2026-10-08 · **Решили:** Паша

## Контекст
Пороги и веса в `contracts/scoring.json` и выбор f0-движка надо обосновать цифрами, а не «подобрали на глаз». Жюри оценивает технические решения. Паттерн взят из курсовой практики по MLflow.

## Решение
- MLflow Tracking Server поднимается **только локально / на CUDA-сервере** (`deploy/mlflow/compose.yml`: tracking server, backend store Postgres или SQLite, artifact store — локальный volume или MinIO). В игровом рантайме MLflow не участвует.
- Скрипт `backend/experiments/eval_scoring.py` прогоняет оценку по датасетам и логирует run.
- **Датасеты** (`mlflow.data`, с source и digest): `golden` — 10–15 реальных дублей команды с человеческой оценкой Сени (аудио вне репо, `data/golden/`, метаданные в репо); `synthetic` — генерируемые дубли (точно, ±50/100/150 центов, задержка 250 мс, октава, тишина).
- **Params:** содержимое `scoring.json`, `f0_engine`, hop, conf_min.
- **Metrics:** главная — Spearman ρ итогового балла с оценкой Сени; вспомогательные — MAE грейдов строк, доля пройденных синтетических кейсов, ошибка оценки задержки (мс), `f0_ms` на секунду аудио, note-F1 UltraSinger против наших MIDI-эталонов.
- **Artifacts:** графики «голос vs ноты» по худшим дублям, матрица грейдов, таблица по строкам, сам `scoring.json`.
- Эксперименты: SwiftF0 vs torchcrepe vs кадры pitchy; допуски 100/120/150 центов; веса 0,65/0,25/0,10 vs 0,7/0,2/0,1.
- Лучший вариант коммитится в `contracts/scoring.json`, id run записывается в заметку [[Оценка и объяснение]] и в слайд.

## Альтернативы
Таблица в заметке без трекинга; Weights & Biases; MLflow Model Registry с alias `champion` и загрузкой скорера в рантайме.

## Последствия
Registry + alias `champion` (скорер как pyfunc, бэкенд грузит `models:/karaoke-scorer@champion` на старте) — **stretch**: красиво для питча, но добавляет зависимость от MLflow во время демо. В MVP версия оценки фиксируется полем `version` в `scoring.json`.
