# ADR-024 Лидерборд из опубликованных каверов

**Статус:** принято · **Дата:** 2026-10-16 · **Заменяет часть:** [[ADR-023 Опубликованные дубли]] (п. 7 и «Последствия» про лидерборд)

## Контекст
- ADR-023 добавил публикацию дубля как отдельный слой: лидерборд по-прежнему показывал лучший `ok`-дубль игрока, а опубликованный, но не лучший дубль в нём не был виден.
- Продукт хочет, чтобы таблица была витриной каверов: любую строку можно открыть и послушать. Игрок сам решает, какой дубль показать, даже если у него есть дубль с большим счётом.

## Решение
1. **В лидерборд попадают только опубликованные `ok`-дубли.** Неопубликованные, даже `ok`, в таблицу не идут. `attempts` по-прежнему считает все `ok`-дубли игрока на песне и сложности.
2. **Одна публикация на игрока.** `POST /published` в той же транзакции снимает прежнюю публикацию этого `client_id` на той же песне и сложности. Опубликованный дубль заменяет строку игрока, даже если его счёт ниже прежнего. Гостевые дубли без `client_id` опубликовать нельзя (`not_owner`, как в ADR-023).
3. **`leaderboard` в ответе `POST /takes`** — место, которое дубль займёт, если его опубликовать: `rank` — среди опубликованных строк других игроков (+1), `of` — их число +1, `personal_best` — лучший ли это `ok`-дубль игрока. `null`, если дубль не `ok`. Формат `{rank, of, personal_best}` не меняется.
4. **`GET /songs` `top`** — первая строка того же лидерборда, то есть лучший опубликованный кавер.
5. **Мост.** `listen` получил паузу и перемотку: `listen_pause()`, `listen_resume()`, `listen_seek(t)`, `listen_state()` → JSON `{take_id, state: idle|loading|playing|paused, t, duration}`. Конец, остановка и ошибка по-прежнему приходят ровно одним `on_listen_end`. Для экрана результата добавлен плеер своего последнего дубля из памяти страницы: `review_play(from)`, `review_pause()`, `review_seek(t)`, `review_stop()`, `review_state()` → JSON `{available, state: idle|playing|paused|ended, t, duration, song_id, take_id}`.
6. **Godot.** Кнопка «Опубликовать кавер» — только на экране результата после настоящего пения (не в «Мой последний результат») и только для `ok`-дубля. Перед публикацией — подтверждение; если в таблице уже есть кавер игрока, показываются его очки и место и новое место, а если новый хуже — отдельное предупреждение. Клик по строке лидерборда открывает окно кавера: место под персонажа автора, ник, место, очки и ранг, плеер, подробности ранга и комментарии по строкам (из `GET /takes/{id}`), у своей строки — «Снять публикацию» с подтверждением.
7. **Дуэли не меняются.** `duel.py`, `/challenges` и `/takes/{id}` прежние.

## Альтернативы
- **Лучший дубль + отметка ♪ у опубликованных (как в ADR-023).** Отвергнуто: строку нельзя заменить дублем ниже, а часть строк нельзя послушать.
- **Отдельная таблица каверов рядом с лидербордом.** Отвергнуто: две таблицы на одном экране путают.
- **Колонка `published` в `takes`.** Отвергнуто: нужна миграция; `published_takes` уже есть.

## Последствия
- После выката таблица пустеет, пока игроки не опубликуют каверы: старые `ok`-дубли без публикации из неё пропадают. Это осознанно.
- Снятие публикации убирает игрока из таблицы целиком: другие его дубли автоматически не подставляются.
- Опубликовать заново можно только с экрана результата сразу после пения (Godot не показывает список старых дублей).
- Риск реплея опубликованного WAV из ADR-023 остаётся.
