# Оценка и объяснение

**f0.**
- `F0_ENGINE=swiftf0` (по умолчанию): swift-f0==0.1.2, `SwiftF0(fmin=65, fmax=1400, confidence_threshold=0.5).detect_from_array(x, 16000)`, hop 16 мс.
- На CUDA: `torchcrepe full`, hop 10 мс, periodicity < 0,1 → 0.
- Если f0 упал, берём `meta.frames`.
- Предобработка: high-pass 70 Гц, RMS-гейт −50 dBFS. Кадр озвучен при `conf ≥ 0,5` и `rms > гейта`. Медианный фильтр на 5 кадров по центам.
- Всё сводится на сетку 10 мс.

**Задержка.**
- `r[k]` = 1 внутри нот, `v[k]` = 1 на озвученных кадрах, оба сигнала центрируются.
- `L* = argmax Σ(v[k+L]−v̄)(r[k]−r̄)` по `L ∈ [−100, 500]` мс через FFT.
- `L** = argmax H(L)` (доля попаданий по тону) в `L* ± 50` с шагом 10.
- `ρ` — нормированная корреляция в пике. Если `ρ < 0,2`, то `applied = hint`, иначе `applied = clip(L**, hint ± 120)`.
- `residual = L** − applied` уходит в ритм.

**Нота.** Окно `[t, t+d]` после `applied`, `m = 69 + 12·log2(f/440)`.
- `dc = ((100·(m−midi) + 600) mod 1200) − 600`, это питоновский `%`.
- Попадание: `|dc| ≤ tol_c`.
- `coverage` = озвученные кадры / все кадры ноты.
- `hit` = попавшие кадры / все кадры ноты. Для rap: `hit = coverage`.
- `cents` = медиана `dc` по озвученным кадрам.
- `onset_ms`: первый из 3 подряд кадров с `|dc| ≤ tol+50`, ищем в `[t−0,15; t+min(0,4; 0,6d)]`.
- `stab_c` = std(dc − скользящее среднее 150 мс), без первых 80 мс.
- `perfect` = `hit ≥ 0,9` и `|onset| ≤ 80`.

**Агрегация.** `w = len·mult[type]`.
- `pitch = Σw·hit / Σw` по normal и golden.
- `rhythm = Σw·coverage·f(onset) / Σw`, где f = 1 при ≤80 мс и линейно падает до 0 к 300 мс.
- `extras = Σlen·perfect / Σlen`. Вибрато — stretch.
- `total = round(10000·(0,65·pitch + 0,25·rhythm + 0,10·extras))`.
- Строка = `100·(0,7·pitch + 0,3·rhythm)`. Грейды по scoring.json.
- `live_total` считается тем же ядром по `meta.frames` и только логируется.

**Подсказки.** По приоритету, не больше 3 общих и по 1 на строку:
1. `silence` (coverage строки < 0,2).
2. `golden_miss` (golden-нота с hit < 0,5).
3. `flat/sharp`: `|cents| > 0,6·tol` и ≥60% нот строки с одним знаком.
4. `late/early`: средний onset > 120 мс или `|residual| > 120`.
5. `unstable`: stab_c > 60 на нотах длиннее 0,4 с.
6. `octave_info`: без штрафа.
7. `praise`: строка ≥ 90.
8. `latency_info`: «скорректировали задержку на {applied} мс».

**Тесты** (pytest, синтетика из reference.json: пила с гармониками, ФНЧ, розовый шум 20 дБ, 48 кГц, всё в памяти):
1. Точное попадание: ≥9500, все строки Perfect, |lag| ≤ 10.
2. Сдвиг на +50, +100, +150 центов: проверка по сложностям, подсказка sharp ~150±15.
3. Задержка 250 мс без hint: estimated 250±10, итог ≥9300.
4. Опоздание только в строке 3: падает ритм этой строки, подсказка late.
5. Октава ±12: итог в пределах ±1%, подсказка octave_info.
6. Тишина или шум: ≤200, подсказка silence, без исключений.
7. Случайный тон: <2000. Свёртка: d(1150) = −50, d(−1150) = 50, d(1200) = 0.
8. Не спеты только golden-ноты: потеря ровно 2w.
9. Самопроверка каждого songs/* по guide.mp3 (§6.5).
10. Golden-набор Сени (10–15 реальных дублей) попадает в коридоры.
11. Контракт-тест: mock/*.json и ответы API валидны по `contracts/*.schema.json`.
