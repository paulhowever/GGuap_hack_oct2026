# Контракты

Сквозные соглашения:
- Время в JSON задаётся в секундах song-time (0 соответствует началу minus.mp3) с 3 знаками после запятой.
- Задержки передаются в мс, у таких полей суффикс `_ms`.
- Основное поле высоты — `pc`. `midi` используется только для отрисовки.
- Типы нот: `normal|golden|free|rap|rap_golden`.

## 3.1 Мост `window.voice`
Одинаков в voice.js и voice.mock.js.

| Вызов Godot→JS | Результат |
|---|---|
| `subscribe(cb)` | `cb(name:string, json:string)` для всех событий |
| `unlock()` | Только из DOM-клика по оверлею. Создаёт ctx, делает resume, вызывает getUserMedia, addModule, регистрирует worklet и 1 с меряет шум. Возвращает `Promise<boolean>`. Godot получает `on_unlocked` |
| `configure(json)` | `{difficulty, lag_ms, music_volume, aec}` |
| `load_song(id)` | GET /api/v1/songs/{id} и decode минуса. Затем `on_ready`. Любой сбой загрузки — `net`, ошибка декодирования минуса — `decode_failed` |
| `start()` / `stop()` | Минус и запись. `stop` готовит WAV. `stop()` вручную не шлёт `on_song_end` и вердикты оставшихся нот; после «Выйти» сразу вызывать `submit()` |
| `poll(): string` | См. ниже. Очередь кадров ≤ 2000 |
| `submit(player, challenge_id)` | POST /takes с таймаутом 10 с. Затем `on_result` или `on_error` |
| `calibrate(mode)` | `mode`: `'speakers'` (по умолчанию) или `'headphones'` — 2 вводных щелчка + 8 измеряемых через 0,8 с, игрок хлопает в такт, задержка до 700 мс ([[ADR-020 Калибровка в наушниках и источник задержки]]). Даёт `on_calibrated`. Необязательна: только в «Настройки → Точная подстройка», задержка подстраивается сама ([[ADR-021 Автоподстройка задержки]]) |
| `client_id()` | uuid игрока из `localStorage` ([[ADR-015 Вход по нику без пароля]]) |
| `publish(take_id)` | Добавлено ([[ADR-023 Опубликованные дубли]]). POST /published со своим `client_id`, для дубля из последнего `on_result` — с его `wav_t0`, иначе `wav_t0: null`; таймаут 5 с. `Promise<boolean>`, затем `on_published` |
| `unpublish(take_id)` | Добавлено (ADR-023). POST /published/{take_id}/remove. `Promise<boolean>`, затем `on_published{published:false}` |
| `listen(take_id)` | Добавлено (ADR-023). GET /published/{take_id}, вокал и минус на общем AudioContext, минус через громкость `music_volume`, вокал сдвинут на `offset_s`; минус не загрузился — голый вокал. `Promise<boolean>`: `true` — заиграло, затем `on_listen`; иначе `on_listen_end{reason:'error'}`. Новый `listen` останавливает предыдущий |
| `listen_stop()` | Добавлено (ADR-023). Останавливает прослушивание, `true` — если что-то играло или грузилось; тогда `on_listen_end{reason:'stopped'}`. `start()`, `calibrate()` и `load_song()` вызывают его сами |
| `listen_pause()` / `listen_resume()` / `listen_seek(t)` | Добавлено ([[ADR-024 Лидерборд из опубликованных каверов]]). Пауза, продолжение с места паузы и перемотка текущего прослушивания (секунды от начала, минус перематывается вместе с вокалом). `true`, если применилось. Пауза не завершает прослушивание: `on_listen_end` не приходит |
| `listen_state(): string` | Добавлено (ADR-024). JSON `{take_id, state: idle\|loading\|playing\|paused, t, duration}` |
| `review_play(from)` / `review_pause()` / `review_seek(t)` / `review_stop()` | Добавлено (ADR-024). Плеер своего последнего дубля из памяти страницы (экран результата): голос поверх минуса, сдвиг `wav_t0 − applied_ms/1000`. `from < 0` — с текущей позиции, после конца — с начала. Отказывает во время песни, калибровки и до `unlock`. `listen` и `review_play` останавливают друг друга |
| `review_state(): string` | Добавлено (ADR-024). JSON `{available, state: idle\|playing\|paused\|ended, t, duration, song_id, take_id}`; `available: false` — дубля в памяти нет (перезагрузка страницы, мок без пения) |

События JS→Godot: `on_unlocked{sr,noise_db,lag_ms,bt_suspect}`, `on_ready{reference…, scoring:{tol_cents}, lag_ms}` (сложность задаётся `configure` до `load_song`), `on_song_end{t}`, `on_result{result.json}`, `on_calibrated{lag_ms,hits,mode}`, `on_error{code,msg}`, `on_note_judged{i,line,type,hit,cents,onset_ms}` — в конце каждой ноты, для реакций продюсера; `hit` — доля кадров ноты в допуске 0..1, попаданием считаем `hit ≥ 0.5` ([[ADR-016 Живой судья нот в voice.js]]). Реакции продюсера опираются на `hit`, `onset_ms` — только для подсказок. Пока `lag_source = estimated`, ноте засчитываются хорошие кадры в 150 мс до и после неё, а вердикт приходит через 150 мс после конца ноты ([[ADR-021 Автоподстройка задержки]]).

События каверов, добавлены ([[ADR-023 Опубликованные дубли]]):
- `on_published{take_id,published,ok,code}` — после `publish` (`published: true`) и `unpublish` (`false`); `code` — `null` при `ok`, иначе `detail` бэкенда (`take_not_found`, `not_owner`, `take_not_ok`, `audio_not_found`, `not_published`, `bad_body`), `http_<статус>` без `detail` или `net` (сеть, таймаут).
- `on_listen{take_id,duration}` — прослушивание началось, `duration` в секундах от старта до конца вокала.
- `on_listen_end{take_id,reason,code}` — ровно один на каждый `listen`: `reason` — `ended|stopped|error`, `code` — `null` или `audio_locked` (до `unlock`, во время песни или калибровки, AudioContext остановлен), `not_published`, `net`, `decode_failed`, `http_<статус>`. Ошибки прослушивания и публикации в `on_error` не приходят.

Коды ошибок:
- `insecure_context|mic_denied|mic_not_found|audio_locked|worklet_failed|decode_failed|net|upload_failed`.

poll:
```json
{"t_now":12.345,"state":"idle|playing|ended","level":0.041,
 "frames":[{"t":12.301,"hz":261.6,"conf":1,"rms":0.042},{"t":12.312,"hz":0,"conf":0,"rms":0.004}]}
```
Отсчёт 3-2-1 Godot рисует сам, пока `t_now < stats.first_note`. Перед первой нотой в файле не меньше 2,5 с, поэтому offset не нужен.

## 3.2 reference.json (schema 1)
```json
{"schema":1,"id":"kalinka","title":"Калинка","artist":"нар. (И. Ларионов), аранж. команды","language":"ru",
 "audio":{"minus":"/media/kalinka/minus.mp3","guide":"/media/kalinka/guide.mp3","duration":31.0,"offset_ms":0},
 "timing":{"bpm_txt":300.0,"gap_ms":2500,"beat_s":0.05},
 "stats":{"notes":58,"lines":6,"range_midi":[57,74],"difficulty":2,"first_note":2.5,"last_end":29.1,"golden_share":0.09},
 "lines":[{"i":0,"t0":2.5,"t1":5.2,"text":"Калинка, калинка, калинка моя!","notes":[
   {"i":0,"t":2.5,"d":0.3,"beat":0,"len":6,"midi":69,"pc":9,"type":"normal","syl":"Ка"},
   {"i":2,"t":3.1,"d":0.6,"beat":12,"len":12,"midi":65,"pc":5,"type":"golden","syl":"ка, "}]}],
 "source":{"origin":"own_midi|ultrasinger|manual","generator":"UltraSinger x.y","t0_ms":61200},
 "license":{"music":"PD","recording":"CC BY 4.0","attribution":"…","url":null}}
```
Как заполняется:
- Индекс ноты `i` сквозной.
- `t = gap_ms/1000 + beat*beat_s`, где `beat_s = 15/BPM`.
- `midi = pitch + 60`, октава выравнивается по диапазону голоса.
- Весов в файле нет, они берутся из scoring.json.

## 3.3 POST /api/v1/takes
Multipart:
- `audio=take.wav`: mono int16 16 кГц, фолбэк — JS-ресемплер на min(sr, 16000) Гц, частота в `wav_sr`;
- `meta`:
```json
{"song_id":"kalinka","client_id":"7b1e…","player":"Паша","difficulty":"normal","challenge_id":null,
 "session_token":"1791976615117.93968ac21cfd505c.2d85…",
 "wav_t0":-0.153,"wav_sr":16000,"lag_ms":48,"lag_source":"calibrated","frames":[…],
 "client":{"ua":"…","sr":48000,"base_latency":0.005,"output_latency":0.012,"aec":false}}
```
`wav_t0` — song-time первого сэмпла без вычета задержки. Бэкенд считает `t_sung = wav_t0 + i/sr − applied_ms/1000`.

`lag_source` — откуда взят `lag_ms`: `calibrated` (калибровка), `config` (`configure`/`config.js`), `estimated` (оценка браузера), `auto` (подстроен по `latency.estimated_ms` прошлых дублей, [[ADR-021 Автоподстройка задержки]]); необязателен, другое значение — 422 `bad_meta`. Правило задержки ([[ADR-020 Калибровка в наушниках и источник задержки]]): при `ρ ≥ rho_min` для `calibrated` `applied = clip(estimated, lag_ms ± lag_clip_ms)`, для остальных и без ключа `applied = estimated`; при `ρ < rho_min` `applied = lag_ms` (или 0), `residual_ms = 0`.

`session_token` — из `POST /api/v1/sessions` перед стартом песни: одноразовый, живёт 900 с, для клиента непрозрачен. Без токена дубль получает `integrity.status = unverified` и в лидерборд не идёт. Повторный `submit()` отправляет тот же дубль без токена: `unverified` (недопетый — `incomplete`), а если первая отправка сохранилась — `suspect` с флагом `duplicate`.

## 3.4 result.json (score-v1)
```json
{"take_id":"tk_7f3a","song_id":"kalinka","client_id":"7b1e…","player":"Паша","difficulty":"normal","version":"score-v1",
 "engine":{"final":"swiftf0-0.3.0","live":"pitchy-mpm"},
 "latency":{"hint_ms":48,"estimated_ms":212,"applied_ms":168,"residual_ms":44,"confidence":0.71},
 "score":{"total":7840,"max":10000,"grade":"A","pitch_pct":81.2,"rhythm_pct":74.5,"extras_pct":38.0,"live_total":7610,"source":"final"},
 "lines":[{"i":0,"t0":2.5,"t1":5.2,"text":"Калинка…","score":92,"grade":"Perfect","pitch_pct":95,"rhythm_pct":86,"tip":null}],
 "notes":[{"i":0,"line":0,"hit":0.94,"cents":-12,"onset_ms":35,"stab_c":18,"perfect":true,"pts":212}],
 "chart":{"hop_ms":20,"t0":2.0,"sung":[null,68.9,69.1]},
 "tips":[{"code":"flat","sev":"warn","line":3,"text":"«Ой, ты…» ниже на ~70 центов"}],
 "octave_shift":0,
 "integrity":{"status":"ok","flags":[]},
 "completion":{"ratio":1.0},
 "challenge":{"id":"ab12cd","opponent":"Макс","opponent_total":7320,"delta":520,"verdict":"win","lines_won":5,"lines_lost":3},
 "leaderboard":{"rank":3,"of":27,"personal_best":true}}
```
`integrity` — проверки честности ([[ADR-017 Объём MVP и решения после ревью]], [[ADR-018 Ранний выход и статус incomplete]]). `status`: `ok` — всё пройдено; `unverified` — нет токена сессии (флаг `no_session`); `incomplete` — недопето: запись кончилась раньше `last_end − 0,5 с` (флаг `incomplete`), в лидерборд не идёт; `suspect` — есть хотя бы один из флагов `bad_session` (подпись не сошлась, чужие песня, сложность или игрок, токен истёк или уже использован), `too_fast` (дубль пришёл раньше `issued_at + max(0, min(duration, конец записи)) − 2 с`, конец записи — `wav_t0 + длина WAV`), `duplicate` (этот WAV уже присылали), `replay` (запись повторяет guide или минус), `not_voice` (слишком ровный тон или нет гармоник голоса). Приоритет статусов: `suspect` > `incomplete` > `unverified` > `ok`. Флаги идут в порядке `no_session`, `bad_session`, `too_fast`, `duplicate`, `replay`, `not_voice`, `incomplete`. Оценку integrity не меняет.
`completion {ratio}` — доля допетого: `1.0`, если у дубля нет флага `incomplete`; у недопетого `ratio = min(0.99, floor(raw · 100) / 100)`, где `raw = clamp((конец записи − first_note) / (last_end − first_note), 0, 1)` (`raw = 1`, если `last_end ≤ first_note`), так что недопетый никогда не показывает 100 %. `first_note` и `last_end` — из `stats` эталона, если их нет — минимальное `t` и максимальное `t + d` по нотам. Недопетые ноты считаются промахами, дубль оценивается и сохраняется как обычно; Godot показывает «допето N%».
`leaderboard` — `{rank, of, personal_best}`: место, которое займёт этот дубль, если его опубликовать ([[ADR-024 Лидерборд из опубликованных каверов]]): `rank` — среди опубликованных строк других игроков на этой песне и сложности, `of` — их число + 1, `personal_best` — лучший ли это `ok`-дубль игрока; `null`, если дубль не `ok`. `challenge` — `null` без `challenge_id`; иначе сравнение с владельцем вызова: `delta = total − opponent_total`, `verdict` по знаку `delta`, `lines_won`/`lines_lost` — строки, где очков больше/меньше, чем у владельца. Godot обязан переживать `null` в обоих полях. `opponent` — ник владельца из профиля, если у его дубля есть `client_id` с профилем, иначе имя из дубля ([[ADR-019 Публичные данные и честность дуэлей]]). `client_id` в ответе `POST /takes` настоящий, в `GET /takes/{id}` — `null`. `octave_shift` — на сколько октав игрок пел от эталона (−1, 0, +1). `chart.sung` уже свёрнут в октаву эталона. Эталонные ноты Godot берёт из reference.

Значения и `null`: `score.grade` — `D` ниже порога `grades.C`; `lines[].grade` — `Miss` ниже `line_grades.OK`; `tips[].sev` ∈ {`warn`, `info`, `good`}; `tips[].line` — `null` у общих подсказок; `notes[].cents`, `onset_ms` и `stab_c` — `null` у неспетых или слишком коротких нот; `latency.hint_ms` — `null` без `lag_ms` в meta; `score.live_total` — `null` без `frames`.

## 3.5 REST
Все пути начинаются с `/api/v1`, кроме `/healthz`, `/media/*` и `/c/{id}` (см. [[ADR-013 Устройство бэкенда]]). Служебные: `GET /healthz`, `GET /api/v1/version`, `GET /api/v1/health`.

Ошибки — JSON `{"detail": "<код>"}`: `song_not_found`, `take_not_found`, `challenge_not_found`, `player_not_found` (404), `take_too_long` (413), `bad_meta`, `bad_audio`, `avatar_too_large`, `challenge_difficulty`, `challenge_take_not_ok` (422); ошибки валидации тела FastAPI — 422 со списком в `detail`. Добавлены для каверов ([[ADR-023 Опубликованные дубли]]): `not_published`, `audio_not_found` (404), `not_owner` (403), `take_not_ok`, `bad_body` (422). В мосте при `submit()` сбой сети до ответа — `net`, ответ не 2xx — `upload_failed`.

| POST /songs/import (multipart audio + `{title,artist,license_url,license}`) | Отложено ([[ADR-022 Импорт трека после хакатона]]), маршрута нет. План: 202 `{id}`, на сервере без `PIPELINE_SSH` — 503 |
| GET /c/{id} | 302 на `/?challenge={id}`; `id` — 6 символов `[a-z0-9]` |
| POST /players `{client_id,nickname,avatar}` (`avatar` — JSON-объект) | создать или обновить профиль, 200 `{client_id,nickname,avatar}`; 422 при пустом нике или avatar > 4 КБ ([[ADR-015 Вход по нику без пароля]]) |
| GET /players/{client_id} | профиль или 404 |
| POST /published `{take_id,client_id,wav_t0}` | Добавлено (ADR-023). Публикует свой `ok`-дубль, 200 — элемент кавера (см. ниже). `client_id` должен совпасть с `client_id` дубля, `wav_t0` — число в [−5; 5] или `null`; повтор возвращает тот же элемент, `wav_t0` и `published_at` от первой публикации. | POST /published/{take_id}/remove `{client_id}` | Добавлено (ADR-023). Снимает публикацию, 200 `{take_id,published:false}`; дубль и WAV остаются. 404 `not_published`, 403 `not_owner`, неверный `client_id` — 422 FastAPI |
| GET /published?song_id=&difficulty=normal&limit=50 | Добавлено (ADR-023). `{items:[элемент]}` — все опубликованные `ok`-дубли песни на этой сложности, по убыванию очков, при равенстве выше раньше опубликованный; `limit` 1–100; 404 `song_not_found`, без `song_id` — 422 |
| GET /published/{take_id} | Добавлено (ADR-023). Элемент кавера; 404 `not_published` (не опубликован или дубль не `ok`) |
| GET /published/{take_id}/audio | Добавлено (ADR-023). WAV дубля, `audio/wav`, поддерживает Range (206); 404 `not_published`, в том числе если файла нет |

Элемент кавера (ADR-023): `{take_id,song_id,difficulty,player,avatar,total,grade,at,published_at,offset_s,offset_source,audio,minus}`. `player` и `avatar` — из профиля, как в лидерборде; `at` и `published_at` — ISO 8601 UTC; `offset_s` — song-time первого сэмпла WAV: `wav_t0 − latency.applied_ms/1000`, без `wav_t0` вместо него −0,15; `offset_source` — `measured` или `default`; `audio` — `/api/v1/published/{take_id}/audio`; `minus` — `audio.minus` песни или `null`, если песни нет в каталоге. `client_id` нет ни в одном ответе `/published`. `GET /takes/{id}` и `/challenges` не меняются; лидерборд строится из опубликованных дублей (ADR-024).

## 3.6 songs/<id>/
```
song.txt  reference.json  minus.mp3  guide.mp3  cover.jpg  meta.yaml  check.json
```
- `cover.jpg` необязателен; `check.json` тоже: без него песня видна в каталоге.
- mp3: 44,1 кГц, `-q:a 2`, не больше 1 МБ на файл, поэтому LFS не нужен.
- Исходники (полные треки, stems) лежат вне репо, на CUDA-сервере или диске.
